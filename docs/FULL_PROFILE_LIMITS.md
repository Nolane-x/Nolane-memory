# Full-profile limits and residual research debt

The runtime exposes executable implementation support for K0–K5. K5 remains a **research runtime profile**, not a self-awarded external proof certificate.

## Residual research debts intentionally kept explicit

1. `future-query-basis` — finite protected semantic bases cannot prove adequacy for every future natural-language question.
2. `preservation-composition` — bounded typed composition is executable; arbitrary production transforms still require empirical/differential validation.
3. `local-repair-closure` — dependency-directed repair is executable; globally minimal repair cones at very large scale are not claimed.
4. `interference-calibration` — scoped effect evidence and exposure chains exist; thresholds/cross-model transfer require experiments.
5. `witness-cover-optimality` — safety is enforceable; global cost-optimal retention over very large heterogeneous stores remains an optimization problem.
6. `capability-refinement` — exact bounded conformance exists; efficient heterogeneous learned-capability refinement remains research work.
7. `external-validity` — internal formal/fuzz/differential/crash evidence cannot prove real-world natural-language or deployment gains.

## Runtime boundary

- Persistence/serialization is SQLite-based and single-host. Authority-domain semantics, incarnation and writer fencing are explicit, but this is not a distributed consensus package.
- Erasure closure proves only surfaces owned/declared by this runtime. External exports/providers remain obligations or opaque until an integration supplies deletion evidence.
- Connector completeness is capability-bound. A successful transport fetch does not make returned content factually authoritative.
- The independent second kernel is architecturally separate inside this package. It is valuable implementation differential evidence but **not independent external replication**.
- Model extraction machinery manages provenance, verification and promotion boundaries; it does not claim perfect natural-language extraction.
- Benchmark registry enforces fairness metadata but does not fabricate public benchmark scores.

## Definition used for implementation-ready

The package may report `implementation_ready=true` only when its machine-enforced gate passes all required implementation checks: closure surfaces and 48/48 ownership, canonical integrity/no-two-writable-clocks, formal and versioned calculi, deterministic state-model and persistence-layer fuzz, independent differential, canonical fault/lost-response probes, acceptance campaigns, recovery/privacy/publication/flow/resource-pressure race campaigns, stress/ablation/longitudinal protocols. Release packaging additionally requires the 402-section coverage ledger to show 302/302 implementation-testable sections COMPLETE with no MISSING or PARTIAL rows.

`research_complete` is separate and remains false while the external research debts above are open.
